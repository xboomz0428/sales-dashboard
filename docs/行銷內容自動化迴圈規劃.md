```
                         ▼  人工核准（手機上一鍵）
 ┌─────────── ③ 設定（先半自動，再 API）──────────────┐

 │ 花費/CPA/ROAS/費率 │ 素材成效標籤 │ 搜尋字詞 │ 廣告審核狀態 │ 天氣條件結束 │
 └───────────────────────┬───────────────────────────┘
                         ▼
 ┌─────────── ⑤ 統整與修正（每週）──────────────────────┐
 │ 廣告×銷售×檔期×天氣 歸因 │ 標題庫汰換 │ 關鍵字加減 │ 預算重分配 │ 預測 vs 實際 │
 │ 產出「修正建議卡」→ 人工核准 → 回到 ③；學到的東西寫回 ① 的各個庫            │

```

**原則**
1. 前三個月**沒有任何文案或設定會自動上線**，一律人工在手機上核准；自動化的是「蒐集、生成、監控、建議」。
2. 好漢草（草本）所有對外文字必須過《藥事法／食安法／化粧品法》合規關卡，不過就不出門。
3. 每一次修正都記錄「改了什麼、為什麼、14 天後結果」，讓迴圈真的在學。

## 3. ② 生成層：從資料到「活動企劃卡」

### 3.1 觸發
- 檔期前 N 天（大檔 21 天、中檔 10 天、蝦皮月活動 5 天）
- 天氣規則成立（見上表）
- 手動：在儀表板按「幫我規劃一檔」並選品項

### 3.2 輸入（組成一份 brief JSON）
`{ 檔期或觸發原因, 日期區間, 候選品項(來自產品池 top 5 含毛利/客單/回購), 關鍵字(自家 GSC top 20 + Ads 有轉換字詞 + Ubersuggest 建議), 標題庫 BEST 前 10, 內容庫相關 FAQ/評價摘錄, 受眾(GA4 購買者輪廓 + RFM 分層), 去年同檔表現, 預算上限(費率目標 ≤ 5% × 預估營收) }`

### 3.3 生成鏈（每步一個既有 Skill，Claude Code 本機跑；第二階段搬上 Worker 呼叫 Claude API）
1. `audience-profiler` → 本檔 2～3 個受眾卡（誰、痛點、切角）
2. `seo-topic` → 主題群與關鍵字分組（品牌／品類／情境／競品）
3. 標題生成：Google RSA 標題 ×15（≤30 字元）、描述 ×4（≤90）；蝦皮標題（`shopee-title`，≤60 字、前 20 字放主關鍵字）；社群貼文標題 ×5；EDM 主旨 ×5。每個標題標記「來源：標題庫改寫／新創」
4. `brand-writing-style` → FB／IG／Threads 三版文案＋LINE 推播短文＋EDM 內文（`email-newsletter`）
5. **`compliance-copywriting` 合規關卡**（好漢草必跑；母嬰品跑簡版）：逐句標紅禁用字（療效、治療、改善、舒緩、抗菌…），自動給合法替代句；任何一句「不可用」就整卡退回重生，不進下一步
6. `crisis-director` → 發文前風險與互動潛力評分
7. 設定建議（規則＋歷史數據，不靠 AI 猜）：
   - 關鍵字：有轉換字詞 → 完全比對；GSC 高曝光低點擊 → 詞組；新字 → 廣泛＋受眾訊號
   - 否定字：近 90 天花費 > NT$500 且 0 轉換的搜尋字詞
   - 受眾：GA4 購買者 180 天（排除）、加購未結帳 30 天（再行銷）、興趣相似（母嬰／養生）
   - 地區：全台；天氣觸發時依區域加權（北部 +20%）
   - 預算：`min(費率目標 × 預估檔期營收, 月預算餘額)`；出價：歷史 CPA × 0.9 當 tCPA
   - 排程：依 GA4 轉換時段（通常 20–23 時）；落地頁＋UTM（`utm_campaign=檔期代碼`）
8. 寫入 `marketing_briefs`（status = `draft`），LINE 推「有一張企劃卡等你看」

### 3.4 產出格式（一張企劃卡）
```
檔期：立冬暖身檔（11/01–11/10）　觸發：節氣＋北部降溫
品項：暖暖足浴包 10 入（毛利 58%、客單 680、回購 45 天）
受眾：A 久坐上班族女性 30–45｜B 送長輩的子女｜C 回購客（排除新客廣告）
RSA 標題（15）：…  描述（4）：…      ← 合規 ✓ 已審（3 句改寫）
蝦皮標題：…  社群：FB／IG／Threads 三版  EDM 主旨：…
關鍵字：完全 12｜詞組 8｜廣泛 5　否定 14
預算：NT$ 18,000（費率目標 4.5%）　tCPA NT$ 650　排程 全天，20–23 時 +15%
[核准並產生設定檔] [改一下] [退回重生]
```

## 4. ③ 設定層：核准後怎麼上線

| 通路 | 第一階段（3 個月內） | 第二階段 |
|---|---|---|
| Google Ads | 產生 **Google Ads Editor 匯入 CSV**（campaign／ad group／keywords／RSA／negatives）＋ 一鍵複製；人工匯入 | Worker 以 Ads API `mutate` 建立（plan/apply 兩段確認、`validateOnly` 先驗）；**需 Basic 等級＋品牌驗證** |
| 蝦皮／momo | 標題與五個標籤一鍵複製；關鍵字廣告出價表匯出 CSV | 蝦皮開放平台 API（需申請）；momo 無 API，維持人工 |
| FB／IG／Threads | 透過 Make 排程發文（已連接） | MetaAds 連接器授權後可下廣告 |
| LINE 官方帳號 | 沿用 `lineMessage.js`／`dashboard_settings` 的 token 推播 | 同 |
| EDM | Resend 連接器寄分眾名單（RFM 分層） | 同 |

每次上線寫 `marketing_actions`（誰、何時、哪張卡、上了哪些設定），供 ⑤ 歸因。

## 5. ④ 監控層

資料來源：`google_ads_daily`（已規劃）＋新增 `google_ads_assets`（素材標籤與 CTR）、`google_ads_search_terms`、`google_ads_policy`（`ad_group_ad.policy_summary.approval_status`）。

| 警示規則 | 門檻 | 動作 |
|---|---|---|
| CPA 失控 | 連續 2 天 CPA > 目標 × 1.3 | LINE 警示＋建議「降出價 10% 或暫停」 |
| 費率燈號 | 通路費率 > 5% 黃、> 8% 紅（沿用獲利分析） | LINE |
| 預算消耗異常 | 檔期過半消耗 < 50% 或 > 80% | LINE |
| 轉換歸零 | 連續 2 天 0 轉換且花費 > NT$1,000 | LINE＋檢查落地頁 |
| 素材衰退 | 標題 `performance_label` = LOW 且曝光 > 1,000 | 排進 ⑤ 汰換清單 |
| 廣告被拒 | `approval_status` ≠ APPROVED | LINE 立即（多半是健康宣稱，回合規關卡） |
| 天氣條件結束 | 觸發條件連續 3 天不成立 | 建議暫停天氣檔（第二階段可自動） |
| 搜尋字詞浪費 | 新字詞 7 天花費 > NT$500 且 0 轉換 | 排進否定字建議 |

警示統一寫 `marketing_alerts` 表，儀表板「預警中心」分頁與 LINE 同步顯示（不另做通知系統）。

## 6. ⑤ 統整與修正層（每週一 07:00 Worker 跑，產出「修正建議卡」）

1. **歸因表**：`google_ads_daily` × `sales_data`（官網通路）× `marketing_calendar` × `weather_daily` → 每檔「花費／官網營收／ROAS／對比去年同檔／天氣彈性（降溫日 vs 平日轉換率）」
2. **標題庫汰換**：BEST／GOOD 標題進 `title_library`（附 CTR、檔期、品項）；LOW 標題標記淘汰，下次生成時指定「改寫 BEST 的句型，避開 LOW 的句型」
3. **關鍵字加減**：有轉換新字詞 → 建議加完全比對；浪費字詞 → 建議否定；GSC 排名 4–10 且曝光高的字 → 建議加廣告或內容
4. **預算重分配**：依各檔 ROAS 與剩餘月預算，建議「從 X 檔移 NT$ 到 Y 檔」
5. **預測 vs 實際**：沿用 `SeasonalForecastPanel` 的 `forecast_records` 閉迴路，檔期預估營收誤差 > 20% 就調整下次預算公式
6. **受眾修正**：GA4 哪個受眾轉換率高 → 下次 brief 預設加權
7. 全部寫成 `marketing_suggestions`（每條：建議、依據數字、預期影響、一鍵套用），人工核准後回到 ③ 並記 `experiment_log`（改動、日期、14 天後自動回填結果）

## 8. 資料模型（新增 migration 草稿）

```sql
create table marketing_calendar (
  id text primary key,              -- 'solar-2026-立冬' / 'ec-2026-1111' / 'lunar-2026-中元'
  date date not null, end_date date,
  kind text not null,               -- solar_term | lunar_festival | ecommerce | custom
  name text not null, channel text, -- ecommerce 時標 momo/蝦皮/全通路
  lead_days int default 10,         -- 提前幾天觸發生成
  product_tags text[] default '{}', -- 關聯品類
  note text
);
create table weather_daily (
  region text, date date, t_min numeric, t_max numeric, pop int, wx text,
  fetched_at timestamptz default now(), primary key (region, date)
);
create table marketing_rules (
  id uuid primary key default gen_random_uuid(), name text, kind text,   -- weather | calendar | manual
  condition jsonb, product_tags text[], enabled boolean default true
);
create table keyword_pool (
  keyword text, source text,        -- gsc | ads_search_term | ubersuggest | manual
  volume int, clicks int, impressions int, conversions numeric, cost_micros bigint,
  position numeric, trend text, product_tag text, status text default 'candidate', -- candidate|active|negative|retired
  updated_at timestamptz default now(), primary key (keyword, source)
);
create table title_library (
  id uuid primary key default gen_random_uuid(), text text not null, channel text, -- google_rsa|shopee|social|edm|gsc_page
  product_tag text, campaign_id text, label text, ctr numeric, impressions bigint,
  compliance_ok boolean default false, retired boolean default false, created_at timestamptz default now()
);
create table content_library (
  id uuid primary key default gen_random_uuid(), kind text, -- faq|post|review|report
  product_tag text, title text, body text, rating numeric, source text, created_at timestamptz default now()
);
create table marketing_briefs (
  id uuid primary key default gen_random_uuid(), trigger text, calendar_id text, period daterange,
  products jsonb, audiences jsonb, keywords jsonb, negatives jsonb, titles jsonb, descriptions jsonb,
  copy jsonb, settings jsonb, compliance jsonb,   -- {ok, flagged:[{sentence, reason, fix}]}
  status text default 'draft',                   -- draft|approved|live|done|rejected
  created_by text, approved_by text, created_at timestamptz default now(), approved_at timestamptz
);
create table marketing_actions (
  id bigserial primary key, brief_id uuid references marketing_briefs(id), channel text,
  payload jsonb, applied_by text, applied_at timestamptz default now(), external_id text
);
create table marketing_alerts (
  id bigserial primary key, rule text, level text, message text, data jsonb,
  created_at timestamptz default now(), acked_by text, acked_at timestamptz
);
create table marketing_suggestions (
  id bigserial primary key, week date, kind text, suggestion text, evidence jsonb, expected jsonb,
  status text default 'open', applied_action_id bigint
);
create table experiment_log (
  id bigserial primary key, suggestion_id bigint, changed_at timestamptz default now(),
  change jsonb, baseline jsonb, result_14d jsonb, verdict text
);
```
RLS 同既有表；`v_product_pool` 為 view。`google_ads_assets`、`google_ads_search_terms` 補進上游規劃第 5 節。

## 9. 排程總表（Cloudflare Worker cron，UTC）

| cron | 台北 | 工作 |
|---|---|---|

## 10. 合規與風險

1. **藥事法是硬關卡**：好漢草文案沒有 `compliance.ok = true` 不得核准；核准按鈕灰掉。歷史裁處案例已在 `compliance-copywriting` Skill 內。
2. **Google 廣告政策**：健康宣稱、個人困境相關字會被拒登；被拒即回合規關卡，不改字就不重送。
3. **個資**：受眾只用 GA4 聚合訊號與平台內建受眾；不把客戶名單上傳 Customer Match，除非另訂同意流程。
4. **API 存取**：Keyword Planner 與 Ads 寫入都要 Basic 等級＋品牌驗證，第一階段避開；Trends 無公開 API；氣象授權碼免費但有流量上限（每日拉 3 次足夠）。
5. **AI 幻覺**：所有數字（毛利、CPA、月量）由程式從表帶入 brief，AI 只寫字不算數；生成結果附來源標記。
6. **費用雙計**：廣告花費與發票的去重規則沿用上游規劃第 8-2 節。
7. **成本**：Ubersuggest 額度看 `user_limits`；Claude API 第二階段再估，第一階段零增量。

## 13. 加做的七個功能（老闆已拍板：第一批全做、第二批除情緒分析外全做）

每個功能都掛在迴圈的某一段，共用同一套表與排程，不另起爐灶。

### 13.1 耗材回購提醒自動化（掛 ③ 設定／④ 監控）
- **依據**：`RepurchasePanel` 已算每位客戶「平均回單間隔」與逾期倍率（>1.0 到期、>1.5 逾期、>2.0 嚴重）；條件 ≥3 個購買日、往來 ≥60 天。
- **做法**：
  1. 新 view `v_repurchase_due`：品項層級（母乳袋、足浴包、艾草包、養生茶等耗材分類）＋客戶層級，列出「預計到期日 ＝ 上次購買 ＋ 平均間隔」。
  2. Worker 每日 07:00 挑「到期前 7 天」與「逾期 1.5 倍」兩群 → 走合規過的模板（`title_library` 的 EDM／LINE 句型）→ 官網會員走 Resend EDM（含回購券碼＋UTM）、LINE 好友走 LINE 推播、經銷客戶改成業務「該拜訪誰」清單（沿用 `weekly-alert`）。
  3. 每次推播寫 `marketing_actions`（channel = repurchase），14 天後 `experiment_log` 自動回填「有沒有回購」。
- **介面**：行銷作戰室加「本週到期回購」卡：人數、預估金額、「一鍵發送」「先看名單」。
- **指標**：耗材回購率、平均回購間隔縮短、推播後 14 天回購轉換率。
- **需你提供**：官網會員 email／LINE userId 與 `sales_data.customer` 的對照（沒有就只做經銷客戶清單＋官網全體分眾）。

### 13.2 備貨連動（掛 ① 蒐集／② 生成）
- **依據**：`forecast.js` 的季節指數、`marketing_calendar` 的檔期倍率（大檔 3～5 倍、中檔 1.5～2 倍）。
- **做法**：
  1. 先用 `scripts/lc-inspect.mjs` 確認 LC（MariaDB）的庫存表與欄位（目前只對過銷貨表），新增 `lc-stock-sync.mjs` 每日把品項現有庫存、在途、安全量寫進 `stock_daily`（在 ERP 主機跑，與 `lc-sync.bat` 同台）。
  2. `v_product_pool` 加欄位：`stock_on_hand`、`days_of_cover`（庫存 ÷ 近 30 天日均銷量）、`stock_status`（充足／偏低／缺貨）。
  3. 生成企劃卡時：缺貨與 `days_of_cover` < 檔期天數的品項**自動剔除**，卡上顯示「已排除 X 品項（缺貨）」。
  4. 檔期前 21 天跑「備貨建議」：`建議備貨量 = 日均銷量 × 檔期天數 × 檔期倍率 × 季節指數 − 現有庫存 − 在途`，寫 `marketing_suggestions`（kind = restock）。
- **介面**：企劃卡上每個品項附庫存燈號；修正建議卡多一類「備貨」。
- **指標**：檔期缺貨天數、廣告推到缺貨品的花費（目標 0）。

### 13.3 折扣彈性分析（掛 ② 生成的設定建議）
- **依據**：`sales_data.discount_rate` 已有逐筆折扣率；目前只在 KPI 卡算平均。
- **做法**：
  1. 每月 Worker 算 `discount_elasticity`：以品類 × 通路為單位，把近 24 個月交易依折扣率分桶（0、1～10%、11～20%、21～30%、>30%），算各桶的「日均數量、毛利額、客單」；彈性 ＝ 數量變化% ÷ 折扣變化%。
  2. 產出「檔期折扣建議」：在毛利額最大的桶取折扣深度，附上「再深 5% 會多賣多少、少賺多少」兩個數字，寫進企劃卡的 `settings.discount`。
  3. 同時標記「折扣無感品項」（彈性 < 0.5，打折只是送錢）與「折扣敏感品項」（> 1.5，可當檔期引流品）。
- **介面**：獲利分析分頁加「折扣彈性」表（品類 × 通路，燈號）；企劃卡顯示建議折扣與依據。
- **注意**：平台檔期的折扣常含平台補貼，`channel` 要分開算；樣本 < 30 筆的桶不算。

### 13.4 廣告預算總控（掛 ⑤ 統整修正）
- **依據**：`ProfitAnalysisPanel` 已算各通路貢獻利益（營收 − 成本 − 平台／物流／廣告費）；`google_ads_daily`、momo／蝦皮廣告費（對帳單）已入 `monthly_expenses`。
- **做法**：
  1. 每月 1 日 Worker 算每通路「邊際 ROAS」：近 3 個月廣告費每多 1 元換到的貢獻利益（用月度資料做簡單回歸，資料不足就用平均）。
  2. 給定月預算上限（`dashboard_settings.ad_budget_monthly`，老闆在設定頁填）與費率目標，產出分配建議：邊際 ROAS 高的通路加、低的減，單通路單月調幅上限 ±30%。
  3. 寫 `marketing_suggestions`（kind = budget），核准後進 `marketing_actions`，下月自動對照實際。
- **介面**：行銷作戰室「本月預算」卡：總預算進度條、各通路配額 vs 實際、建議調整箭頭；設定頁加月預算與費率目標欄位。
- **指標**：整體廣告費率、貢獻利益／廣告費。

### 13.5 官網轉換漏斗（掛 ④ 監控）
- **依據**：GA4 Data API `runFunnelReport`（官方 MCP 也有 `run_funnel_report`）；Ubersuggest `pagespeed_audit`。
- **做法**：
  1. Worker 每日拉漏斗：商品頁 → 加入購物車 → 結帳開始 → 付款完成，依來源（廣告／自然／直接／社群）與裝置分段，寫 `ga4_funnel_daily`。
  2. 每週跑官網首頁與前 5 個廣告落地頁的 pagespeed（手機分數、LCP），寫 `page_speed_weekly`。
  3. 警示規則加三條：某步驟流失率較 4 週均值惡化 > 20%；廣告來源的加購率低於自然來源一半（落地頁與廣告承諾不符）；落地頁手機分數 < 50。
- **介面**：流量與搜尋頁加「漏斗」卡（四步驟橫條、每步流失%、燈號）；廣告活動卡顯示落地頁分數。
- **指標**：加購率、結帳完成率、廣告來源 vs 自然來源轉換率差距。

### 13.6 SEO 內容產文（掛 ② 生成，另一條支線）
- **依據**：GSC 查詢字（`gsc_daily`）、`keyword_pool`、`google-official-seo-guide` 與 `seo-topic` Skill、知識庫 FAQ。
- **做法**：
  1. 每週從 `keyword_pool` 挑「排名 4～10、曝光 ≥ 500、CTR 低於同排名基準」的字詞，分群成文章主題（每週 2～3 篇），寫 `content_briefs`。
  2. 生成鏈：`seo-topic`（大綱、FAQ 區塊、內鏈建議）→ 內文 1,200～1,800 字（引用 `kb_faqs` 與評價摘錄）→ **合規關卡**（好漢草同樣硬擋）→ `title_library` 收錄標題 → 狀態 draft。
  3. 核准後匯出 Markdown／HTML，先人工貼到官網部落格；官網 CMS 若有 API 再接。
  4. 發布 4 週後回填該字詞排名與點擊變化到 `experiment_log`。
- **介面**：行銷作戰室「內容」分頁：待審文章卡（標題、目標字詞、預估流量、合規狀態）。
- **指標**：目標字詞排名進前 3、自然流量占比、自然來源營收。

### 13.7 競品監控（掛 ① 蒐集）
- **依據**：Ubersuggest `competitors`、`domain_overview`、`domain_keywords`、`serp_analysis`、`brand_visibility_overview`。
- **做法**：
  1. 在設定頁維護 5～8 個競品網域與 10 個核心字詞。
  2. Worker 每週一：各競品的流量估計、關鍵字數、新進前 10 的字詞；10 個核心字詞的 SERP 前 10 標題與我方排名；AI 搜尋（brand visibility）我方 vs 競品被提及比例。寫 `competitor_weekly`、`serp_weekly`。
  3. 競品前 10 標題自動進 `title_library`（channel = competitor，不可直接複製，只當句型參考）；競品新上榜字詞進 `keyword_pool`（source = competitor）。
  4. 警示：核心字詞我方排名掉出前 10；競品流量週增 > 30%。
- **介面**：行銷作戰室「競品」卡：10 個核心字詞的我方 vs 最強競品排名表、競品流量趨勢小圖。
- **注意**：蝦皮／momo 站內競品價格沒有合法 API，不做自動抓取；需要時人工匯入 CSV。
